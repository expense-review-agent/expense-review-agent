# Interaction Patterns

## 壹、核心原則

CheckMate 的互動設計必須讓使用者快速完成三件事：

1. 看懂 Agent 的結論。
2. 確認結論是否有足夠依據。
3. 採取正確的下一步。

互動順序採 **Outcome-first + Evidence-first**，不讓使用者先閱讀大量 AI 推理才知道結果。

## 貳、案件審查模式（Case Review Pattern）

案件詳情（Case Detail）建議流程：

案件摘要（Case Summary）→ 審查建議（Recommendation）→ 阻擋風險／風險訊號（Blocking / Risk Signal）→ 必要檢核（Required Checks）→ 發現項目（Finding）→ 佐證資料（Evidence）→ 流程動作（Action）→ 稽核紀錄（Audit Record）

審查建議必須在首屏可見。

若存在阻擋型問題（Blocking Issue），不應讓主要動作看起來仍可安全執行 PROCEED。

## 參、發現項目模式（Finding Pattern）

每個發現項目（Finding）至少回答：

- 發現什麼？
- 嚴重程度？
- 依據什麼佐證資料（Evidence）？
- 對應哪一條規則／來源（Rule / Source）？
- 對審查建議（Recommendation）有什麼影響？

避免把多個不同問題塞進一段 AI 摘要（Summary）。

## 肆、佐證資料模式（Evidence Pattern）

佐證資料（Evidence）應盡可能顯示：

- 原始值
- 資料來源
- 對應欄位
- 比對結果
- 必要時顯示原始文件位置

使用者應能從發現項目（Finding）回到佐證資料，而不是只能相信文字摘要。

## 伍、審查建議模式（Recommendation Pattern）

固定三種：

### 建議通過
必要檢查已完成，且沒有阻擋風險。不代表最終核准。

### 建議補件
缺少完成初審所需的資料或證據。必須明確說明「缺什麼」。

### 建議人工審核
存在高風險、不確定、規則衝突或需要專業判斷的情境。必須明確說明「為什麼需要人」。

## 陸、工作流程動作模式（Workflow Action Pattern）

審查建議與流程動作分開顯示。

### PROCEED
用於 Agent 初審已完成且符合自動推進條件。UI 文案應依情境使用「送往下一審核節點」「完成初審」等清楚動詞，避免讓使用者誤解為最終核准。

### REQUEST_INFO
用於缺件或資訊不足。操作前顯示需要補充的項目、通知對象與將執行的動作；執行後留下稽核紀錄（Audit Record）。

### ESCALATE
用於高風險、不確定或需人工專業判斷。清楚說明轉交原因、轉交對象／佇列（Queue）與 Agent 已完成哪些檢查。

### OVERRIDE
人工不同意 Agent 結果時使用。至少記錄原本的審查建議（Recommendation）、人工決策（Human Decision）、覆寫原因（Override Reason）與時間戳記（Timestamp）。

## 柒、自動執行控制模式（Automation Gate Pattern）

在允許 Agent 自動執行前，UI／系統狀態（System State）必須能反映：

- 必要檢核（Required Checks）是否完成
- 佐證資料（Evidence）是否充分
- 規則判斷結果是否明確
- 是否存在阻擋型風險（Blocking Risk）
- 是否存在未解決衝突
- 流程動作是否位於授權範圍

只要任一條件未滿足，自動執行即被阻擋。

不要用單一「AI 信心值（Confidence）」百分比取代上述控制條件。

## 捌、確認模式（Confirmation Pattern）

REQUEST_INFO、ESCALATE、OVERRIDE 與任何可能改變案件流程狀態的動作建議要求確認。

Confirmation 應寫清楚「即將發生什麼」，而不是只問「確定嗎？」

例如：

> 即將要求申請人補上住宿發票。送出後，案件會進入等待補件狀態。

## 玖、狀態文案（Status Wording）

建議：

- 待審查
- 審查中
- 待補件
- 待人工審核
- 初審完成
- 已轉交

避免：

- AI 思考中
- AI 不太確定
- 看起來沒問題
- 可能安全

## 拾、Loading / Empty / Error

### Loading
可顯示實際階段，例如正在整理案件資料、比對憑證、檢查規範或產生審查結果。

### Empty
說明沒有內容的原因，例如「此案件目前沒有需要人工處理的風險項目」。

### Error
明確說明錯誤是否影響資料讀取、某項檢查、審查建議（Recommendation）或流程動作（Action）。

## 拾壹、稽核紀錄模式（Audit Pattern）

稽核時間軸（Audit Timeline）以事件為單位，至少顯示：

- 時間
- 執行者（Actor）：Agent／人工（Human）／系統（System）
- 動作（Action）
- 結果（Result）
- 原因（Reason，如適用）

使用者應能重建案件從進入 CheckMate 到目前狀態的主要決策歷程。

## 拾貳、無障礙設計（Accessibility）

- 所有 Action 可由 Keyboard 操作。
- Drawer / Modal 開啟時正確移動 Focus。
- Status 具文字 Label。
- Error 與 Warning 不只用顏色表示。
- 展開／收合元件具有可辨識的 Accessible Name。

## 本輪工作台操作提案｜2026-09-28

使用者已選定 C 布局，且明確指定此角色直接處理例外案件。以下是探索中的前端流程，優先於本文件上方的一般模式描述；正式授權與流程串接仍待對應 Slice 收斂。

- 建議通過：先顯示核對摘要，再確認「完成初審」，不稱為最終核准。
- 建議補件：先顯示缺少項目；「退回補件」對話框列出申請人及可編輯內容。
- 建議人工審核：先顯示具體問題及數值對照，由目前使用者要求補件，或填寫審核說明後完成初審；不以再次轉交人工作為主要動作。
- 原始建議保持不變，人工結果另外記錄；任何處理僅作用於最新紀錄，處理後不再提供重複送出入口。
- 對話框清楚說明為模擬操作；帳號選單提供展示範圍說明。重新整理還原所有處理結果。
- 案件編號與申請人條件採 AND，初審建議複選採 OR；空篩選代表全部。切換分類或查詢使目前案件不在結果中時，關閉詳情。
- 上一筆／下一筆只在目前篩選結果內循環。歷史紀錄可查看，不能處理。
- 單筆處理不代表自動執行門檻已實作；補件回流、再次覆寫及持久化均不在本輪。

### 本輪整合：批次操作與費用核對

- 保留全部、建議通過、建議補件、建議人工審核四個列表檢視。摘要獨立成欄，截斷顯示且完整內容保留在詳情，不限制申請人輸入字數。
- 建議通過檢視可勾選未處理案件。確認時列出案件及總額；整批皆須仍為建議通過且未處理，否則不執行。重複 ID、空選取也不接受。變更查詢／篩選清除選取；完成後保留原始建議、各筆處理紀錄，不重複處理。
- 三類案件共用完整詳情：申請資料、費用明細、對應憑證、檢查結果、歷史。通過案件預設展開檢查結果，不隱藏證據。列表及詳情仍是同一工作台，可展開詳情再返回並排。
- 明細金額核對與案件建議不同：金額一致不代表規範符合。每筆明細以 evidenceIds 對應當次審查憑證，歷史紀錄不能顯示後來補入的附件。
- 建議補件可退回整筆案件，或填寫依據後人工確認通過；人工結果不覆蓋原始建議。其他案件也可退回補件。確認完成不代表最終核准。
- 八筆模擬案例包含多筆費用缺件與一筆建議通過。所有預覽均是展示用模擬憑證，無真實擷取／通知／外部流程。

驗證：核心批次限制與人工確認原因採自動測試；瀏覽器抽查批次確認、多筆明細切換及通過案件憑證。這些仍是 Prototype 行為，正式自動化授權未定案。

### 最新資訊架構：依處理進度分流

- 第一層為待處理、待補件、已完成初審、全部，顯示各狀態總筆數；三種初審建議改為第二層複選篩選。預設待處理。搜尋與建議條件在當前進度內套用，切換進度保留條件並清除批次選取。
- 完成／退回後移出待處理列表，詳情隨之關閉。列表上方顯示簡短完成提示，數秒後自動消失，不需要手動關閉，也不提供另外的查看案件入口；要查看剛處理的案件，切換對應進度分頁即可。待補件不算已完成。全部檢視中不移除已處理案件。
- 完整列表由左到右：案件編號、申報項目、初審建議、初審結果、費用類型、申請部門、申請人、申請金額、處理狀態、申請日期。案件編號與申報項目為凍結欄位，其餘欄位可左右捲動查看；兩者與初審結果超過兩行以刪節號截斷，Hover 顯示完整內容。初審建議與初審結果欄位以圖示標示為 Agent 產出，圖示採用主色，不用灰階避免不明顯。處理狀態欄位只在「全部」分頁顯示，其餘分頁內容已由分頁本身代表處理狀態，不重複顯示；顯示時採 Chip 樣式而非純文字。批次選取另占控制欄，與案件編號、申報項目一併凍結。並排與展開詳情時列表不整個隱藏，僅變窄並保留凍結欄位與捲動能力。
- 詳情依序：固定案件 Header、申請資訊、審查結果與比對、處理建議、固定操作 Footer。歷史與處理紀錄保留供追溯。申請資料與 Agent 結果不混在同一表格。
- 申請資訊分基本資訊、費用明細、付款資訊。未稅／稅額未提供時明示，不推定稅率或將未提供顯示為零。
- 審查區採檢查項目／比對內容／結果三欄；依據可展開，關鍵異常直接顯示。憑證預覽可依明細切換。紅色人工審核 Chip 表示需人工判斷，不表示已確認違規。
