> 其餘情境（例如二次決策覆寫、REQUEST_INFO 逾期後續處理、多筆風險發現的呈現優先序、法規判斷不明確的標示方式等）列在 [user-flow.md](user-flow.md) 的「Open Questions / Deferred Decisions」，待對應功能開發時再逐步收斂為此文件的正式項目。

## 1. 建議通過但無法由 Agent 自動執行

- **情境**：審查建議（Recommendation）為建議通過，但因授權範圍等條件，Agent 無法自動執行對應動作。
- **目前原則**：Agent 不自動執行，案件轉為人工處理，由人工執行 PROCEED；執行者（Actor）記為人工，動作本身仍是 PROCEED。
- **需注意**：「建議通過」不等於「已自動完成」，兩者需要清楚區分，避免使用者誤判案件已處理完畢。
- **尚未決定**：此類案件在案件狀態上如何呈現（是否需要新增狀態）暫列為待確認事項，待實際開發此流程時再依 UX 與狀態模型一併決定。

---

正常案件初審流程本身不會觸發上述情境；其餘 Edge Case 隨後續 Product Slice（補件、人工審核、決策覆寫等）逐步補充。
