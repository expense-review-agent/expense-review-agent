# reviewer-workbench Specification

## Purpose

M1-U1 Reviewer 工作台前端：讓財務初審人員在案件總覽掌握 Agent 的分流結果，在詳情抽屜看到逐項檢查、
證據與建議，並以合法動作完成初審。顯示層同時守住產品責任邊界：不指控、非通過必示證據、動作只來自
共用矩陣、一致性徽章不重算。

## Requirements

### Requirement: 案件總覽統計與篩選

工作台 SHALL 在案件總覽顯示四分類（`NORMAL / MISSING / EXCEPTION / HUMAN`）統計卡片與待審總數，
且**每張分類卡片本身即為該分類的篩選控制項**——可點選套用、再點選取消，並以可辨識的選取樣式呈現。
待審總數的卡片 SHALL 同時是「**全部**」選項，代表不套用分類篩選，並 MUST 為預設選取項。
任何時候 MUST 恰有一張卡片為選取狀態，工作台 MUST NOT 呈現「沒有任何卡片被選取」的狀態——
使用者必須能從卡片的選取樣式判斷當前的分類範圍。

工作台 SHALL 另提供一組依**處理狀態**（`QUEUED / AWAITING_INFO / DISPOSED`）篩選的控制項，
含「全部」選項。工作台 MUST NOT 另外提供一組依 Agent 分類篩選的控制項列（分類篩選只經由統計卡片）。

兩個篩選維度 SHALL 可同時套用，且 MUST 以 AND 條件組合（分類符合**且**處理狀態符合）。

計數規則——**畫面上只有一個會隨操作變動的數字**，以降低認知負荷並讓每個數字各自只有一種含意：

- **統計卡片的計數是固定的總覽**：一律為待審案件的分類分佈，MUST NOT 隨處理狀態篩選、
  分類篩選或搜尋而改變。卡片回答「整體情勢」，不是「點下去會有幾筆」。
- **處理狀態控制項 MUST NOT 顯示計數**。
- 工作台 SHALL 在篩選控制項與列表之間顯示**單一的結果筆數**（例如「共 2 筆」），
  且它 MUST 等於套用全部生效條件（搜尋 + 分類 + 處理狀態）後列表實際顯示的筆數。
  這是畫面上唯一反映當前結果的數字。
- 所有計數 MUST 依預設列表（已排除 `REVIEW_CLOSED` 案件）計算。已結案案件即使帶有 Agent 分類，
  也 MUST NOT 計入分類卡片與待審總數。
- 列表尚未取得時，卡片與結果筆數 MUST NOT 顯示數字（不得把載入中或失敗顯示為 0）。

當前條件組合沒有任何案件時，工作台 MUST 顯示空狀態說明，並提供清除篩選與搜尋的方式，
MUST NOT 讓使用者停在無法脫離的空列表。

由於卡片是固定總覽，套用處理狀態篩選或搜尋時，卡片的數字可能大於點選後實際顯示的筆數。
這是刻意的取捨：結果筆數由上述單一數字負責，卡片則保持穩定不跳動。

#### Scenario: 統計卡片顯示四分類計數

- **WHEN** Reviewer 開啟案件總覽且未套用任何篩選
- **THEN** 畫面顯示 NORMAL、MISSING、EXCEPTION、HUMAN 四張卡片，各附預設列表中該分類的案件數與對應建議文案

#### Scenario: 預設選取「全部」

- **WHEN** Reviewer 開啟案件總覽
- **THEN** 待審總數（「全部」）卡片為選取狀態並帶選取底色，四張分類卡片皆非選取狀態

#### Scenario: 選取狀態永不為空

- **WHEN** 分類篩選為 EXCEPTION 時 Reviewer 再次點選該卡片取消篩選
- **THEN** 「全部」卡片回到選取狀態，畫面上恰有一張卡片帶選取底色

#### Scenario: 依分類篩選

- **WHEN** Reviewer 點選「EXCEPTION」統計卡片
- **THEN** 列表只顯示 Agent 分類為 EXCEPTION 的案件，該卡片呈現選取狀態

#### Scenario: 取消篩選

- **WHEN** 分類篩選為 EXCEPTION 時 Reviewer 再次點選該卡片
- **THEN** 分類篩選解除，列表回到全部待審案件，該卡片不再是選取狀態，選取底色移回「全部」卡片

#### Scenario: 點選「全部」卡片清除分類篩選

- **WHEN** 分類篩選為 MISSING 時 Reviewer 點選「全部」卡片
- **THEN** 分類篩選解除，列表顯示全部待審案件，選取底色移到「全部」卡片

#### Scenario: 依處理狀態篩選

- **WHEN** Reviewer 選擇處理狀態「待補件」
- **THEN** 列表只顯示流程狀態為 `AWAITING_INFO` 的案件，該控制項呈現選取狀態

#### Scenario: 處理狀態控制項不顯示計數

- **WHEN** Reviewer 檢視處理狀態的篩選控制項
- **THEN** 每個控制項只顯示狀態名稱，不附任何數字

#### Scenario: 兩個維度同時套用為 AND

- **WHEN** Reviewer 同時選擇分類 `MISSING` 與處理狀態「待補件」
- **THEN** 列表只顯示同時符合兩個條件的案件

#### Scenario: 統計卡片的數字固定不隨篩選改變

- **WHEN** Reviewer 依序套用處理狀態「待補件」、分類 `MISSING`、任一搜尋字串
- **THEN** 四張分類卡片與待審總數的數字，在每一步都與未套用任何條件時相同

#### Scenario: 結果筆數反映全部生效條件

- **WHEN** Reviewer 同時套用分類 `MISSING`、處理狀態「待補件」與一段搜尋字串
- **THEN** 篩選控制項與列表之間顯示的結果筆數，等於列表實際顯示的筆數

#### Scenario: 已結案參照案件不計入統計

- **WHEN** 一筆流程狀態為 `REVIEW_CLOSED`、Agent 分類為 NORMAL 的案件存在
- **THEN** NORMAL 卡片、待審總數與結果筆數都不包含該案件

#### Scenario: 篩選組合無結果

- **WHEN** 當前分類與處理狀態的組合沒有任何案件
- **THEN** 列表顯示空狀態說明並提供清除篩選的入口，且結果筆數顯示為 0 筆

### Requirement: 案件列表

工作台 SHALL 以列表呈現案件，每列含案件編號、申請人與說明、費用類別、金額、**申請日期**、
Agent 分類徽章、建議動作與處理狀態。`REVIEW_CLOSED` 的參照案件 MUST NOT 出現在預設列表。
分類為 EXCEPTION 的案件，其金額 MUST 以警示色呈現。金額 MUST 依後端傳來的字串格式化顯示，
不得先轉成浮點數再運算。

列表的日期欄 MUST 為申請日期，與排序入口一致——排序只能作用在列表實際顯示的欄位上，
MUST NOT 排序畫面上不存在的欄位。消費日期 MUST 仍可在案件詳情抽屜查得，
MUST NOT 因列表改為顯示申請日期而從產品中消失。

#### Scenario: 參照案件不進預設列表

- **WHEN** 後端列表含一筆流程狀態為 `REVIEW_CLOSED` 的參照案件
- **THEN** 預設列表不顯示該案件，且待審總數不計入

#### Scenario: EXCEPTION 金額標示

- **WHEN** 某案件 Agent 分類為 EXCEPTION
- **THEN** 該列金額以警示色顯示

#### Scenario: 處理狀態可辨識

- **WHEN** 某案件流程狀態為 `AWAITING_INFO`
- **THEN** 該列處理狀態顯示為「待補件」，與分類徽章分開呈現

#### Scenario: 金額格式化

- **WHEN** 後端傳來金額字串 `"12345.50"`、幣別 `TWD`
- **THEN** 列表顯示 `NT$ 12,345.50`，千分位與小數位與原字串一致

#### Scenario: 非 TWD 幣別明示

- **WHEN** 某案件幣別不是 TWD
- **THEN** 金額前顯示該幣別代碼而非 `NT$`，不做任何換算

#### Scenario: 列表日期欄為申請日期

- **WHEN** Reviewer 檢視案件列表
- **THEN** 日期欄標題為「申請日期」並顯示該案件的申請日期

#### Scenario: 消費日期仍可查得

- **WHEN** Reviewer 開啟某案件的詳情抽屜
- **THEN** 申請資訊同時顯示申請日期與消費日期兩個欄位

### Requirement: 案件詳情抽屜

點選列表中的案件時，工作台 SHALL 在右側開啟詳情抽屜，依序呈現：案件標題與分類徽章、申請資訊、
Agent 檢查清單、Agent 建議、關聯案件（如有）、Reviewer 處置區。抽屜的開啟狀態 MUST 反映在網址上，
重新整理或分享網址後 MUST 開啟同一案件。抽屜 MUST 可用關閉按鈕、點擊遮罩或 Esc 鍵關閉。

申請資訊中的申請人與部門 SHALL 可點選，開啟該申請人或該部門的申請紀錄。對應欄位沒有值時
（例如案件未記錄部門），該欄 MUST 顯示為無值且 MUST NOT 可點選。

#### Scenario: 開啟詳情

- **WHEN** Reviewer 點選某案件列
- **THEN** 右側抽屜開啟並顯示該案件的申請資訊、檢查清單與 Agent 建議

#### Scenario: 以網址直接開啟

- **WHEN** Reviewer 以含某案件識別的網址載入工作台
- **THEN** 案件總覽載入，且該案件的詳情抽屜自動開啟

#### Scenario: 鍵盤關閉

- **WHEN** 抽屜開啟時 Reviewer 按下 Esc
- **THEN** 抽屜關閉，網址不再帶該案件識別

#### Scenario: 案件不存在

- **WHEN** 網址指向的案件 id 後端回 404
- **THEN** 抽屜顯示「找不到案件」訊息，不顯示任何處置按鈕

#### Scenario: 無部門資料時不可點選

- **WHEN** 開啟的案件沒有記錄部門
- **THEN** 部門欄顯示無值符號，且不可點選、不會開啟申請紀錄

### Requirement: 檢查清單以結論呈現且守住不指控原則

工作台 SHALL 將每個檢查呈現為一列白話結論：通過為 ✅、未通過為 ❌、其餘無法由 Agent 下結論的結果
（受阻、退讓、待人工）為 ⚠️「需人工確認」。工作台 MUST NOT 以 ✅ 呈現任何非通過結果。
工作台 MUST NOT 顯示 Agent 內部推理標記：依賴關係 chip、信心度、五態原始值、§ 條號。

標記為「僅疑似」的規則（重複申報、拆單）未通過時，文案 MUST 以「疑似」表述，MUST NOT 使用確定性
的指控字眼。此約束 MUST 對所有疑似類規則一律成立，不得由組織設定或文案覆寫。

#### Scenario: 非通過結果不顯示為通過

- **WHEN** 某檢查的結果為 `GATED`、`ABSTAIN` 或 `PENDING_HUMAN`
- **THEN** 該列以 ⚠️「需人工確認」呈現，不以 ✅ 呈現

#### Scenario: 疑似重複以疑似表述

- **WHEN** 重複申報規則（僅疑似）結果為未通過
- **THEN** 該列標題含「疑似」字樣，不出現「重複申報」這類確定性判定語句

#### Scenario: 內部推理標記不顯示

- **WHEN** 詳情資料含信心度與規則五態原始值
- **THEN** 抽屜畫面上不出現信心度文字與 `GATED`、`ABSTAIN` 等原始值

### Requirement: 非通過檢查顯示證據

每個非通過檢查 SHALL 在該列下方顯示其證據內容。證據含關聯案件時，工作台 MUST 顯示該關聯案件編號，
並可點選切換到該案件詳情。若非通過檢查缺少證據，工作台 MUST 顯示「證據缺漏」警示，不得靜默隱藏。

#### Scenario: 顯示證據片段

- **WHEN** 某未通過檢查附一筆證據片段
- **THEN** 該列下方顯示證據片段原文

#### Scenario: 跨案件證據可導覽

- **WHEN** 疑似重複檢查的證據指向關聯案件 `EXP-2026-1043`
- **THEN** 該列顯示可點選的 `EXP-2026-1043`，點選後抽屜切換為該案件詳情

#### Scenario: 證據缺漏被標示

- **WHEN** 某非通過檢查的證據清單為空
- **THEN** 該列顯示「證據缺漏」警示

### Requirement: Agent 建議呈現

工作台 SHALL 以三桶建議的配色與標題呈現 Agent 建議（建議通過／建議補件／建議人工審核），附白話理由；
若檢查引用了組織規範，MUST 以條文原文列出「適用規範」。分類為 HUMAN 時，建議區 MUST 分三段呈現：
已完成的檢查、Agent 無法確定的項目、建議由人判斷的說明，且 MUST 明示此案超出 Agent 判斷範圍。
工作台 MUST 明示 Agent 建議不是最終決定。

#### Scenario: MISSING 建議補件

- **WHEN** 案件建議為 `REQUEST_INFO`
- **THEN** 建議區以補件配色顯示「建議補件」與理由，並列出適用規範條文原文

#### Scenario: HUMAN 三段式

- **WHEN** 案件分類為 HUMAN
- **THEN** 建議區分段列出已通過的檢查、需人工確認的項目，以及「建議由 Reviewer 判斷」的說明

#### Scenario: 無 run 的案件

- **WHEN** 開啟的案件沒有 Agent run（例如參照案件）
- **THEN** 抽屜顯示「此案件尚無 Agent 初審結果」，不顯示建議區與處置按鈕

### Requirement: 系統文案走 i18n

工作台顯示的系統訊息、狀態、規則理由與動作名稱 SHALL 由訊息鍵與參數組字產生，文案 MUST 集中於
前後端共用的語系表。組織規範條文原文與人工填寫的理由 MUST 原樣顯示，不經轉譯。語系表缺少某訊息鍵時，
工作台 MUST 顯示該結果類型的通用文案，不得把原始訊息鍵或空白顯示給使用者。

#### Scenario: 訊息鍵組字

- **WHEN** 檢查帶訊息鍵與參數，且語系表有該鍵
- **THEN** 畫面顯示代入參數後的中文句子

#### Scenario: 訊息鍵缺漏

- **WHEN** 檢查的訊息鍵在語系表中不存在
- **THEN** 畫面顯示依結果類型的通用句（例如「此項檢查未通過」），不顯示原始鍵

#### Scenario: 規範原文不轉譯

- **WHEN** 檢查引用的規範條文原文為「住宿每晚上限 NT$4,000」
- **THEN** 畫面原樣顯示該條文

### Requirement: Reviewer 處置只提供合法動作

工作台 SHALL 只在案件流程狀態為 `QUEUED` 且有 Agent 建議時顯示處置按鈕。按鈕集合 MUST 由共用合法動作
矩陣依該案建議產生，工作台 MUST NOT 另行定義動作或提供矩陣外的動作（例如「退回申請」「不通過」）。
按鈕文案 MUST 反映該動作在此建議下的語意：建議為 `MANUAL_REVIEW` 時，「採用建議」MUST 表述為轉呈主管，
並說明 Reviewer 不下結論。流程狀態不是 `QUEUED` 時，處置區 MUST 顯示目前處理狀態，不顯示按鈕。

案件已有處置紀錄時，處置區 SHALL 在目前處理狀態同一列顯示**執行處置的人員**與處置時間。
處置人 MUST 取自後端回傳的處置紀錄，工作台 MUST NOT 以當前使用者或任何預設值替代。
案件流程狀態已離開 `QUEUED` 但後端查無處置紀錄時，工作台 MUST 顯示查無處置紀錄，
MUST NOT 顯示空白或猜測的處置人。

#### Scenario: 建議通過的動作集合

- **WHEN** 待審案件建議為 `APPROVE`
- **THEN** 處置區顯示「確認通過」「退回補件」「人工判斷」「暫緩處理」四個動作，沒有其他動作

#### Scenario: 建議補件的動作集合

- **WHEN** 待審案件建議為 `REQUEST_INFO`
- **THEN** 處置區顯示「確認退回補件」「人工判斷」「暫緩處理」，不顯示獨立的「退回補件」

#### Scenario: 人工審核建議轉呈

- **WHEN** 待審案件建議為 `MANUAL_REVIEW`
- **THEN** 「採用建議」按鈕文案為「轉呈主管」，並附說明 Reviewer 不下最終結論

#### Scenario: 已處置案件不顯示按鈕

- **WHEN** 案件流程狀態為 `DISPOSED` 或 `AWAITING_INFO`
- **THEN** 處置區顯示該處理狀態，不顯示任何處置按鈕

#### Scenario: 已處置案件顯示處置人

- **WHEN** 開啟一筆流程狀態為 `DISPOSED` 且有處置紀錄的案件
- **THEN** 處置區在處理狀態同一列顯示該處置的執行人員與處置時間

#### Scenario: 查無處置紀錄

- **WHEN** 案件流程狀態不是 `QUEUED`，但後端未回傳任何處置紀錄
- **THEN** 處置區顯示目前處理狀態與「查無處置紀錄」，不顯示任何人員名稱

### Requirement: 處置送出與理由要求

工作台 SHALL 在送出處置前要求必要資訊：該動作或其結論依共用規則需要理由時，理由欄 MUST 為必填，
空白或只有空白字元時 MUST NOT 送出。「人工判斷」MUST 開啟對話框讓 Reviewer 指定最終結論
（通過／補件／人工審核）與理由；只有「人工判斷」的請求可以帶最終結論，其他動作的請求 MUST NOT 帶。
「確認通過」「轉呈主管」這類不可逆的決定 MUST 經確認步驟才送出。送出期間按鈕 MUST 停用，避免重複送出。

#### Scenario: 人工判斷指定結論

- **WHEN** Reviewer 在建議通過的案件選「人工判斷」，指定最終結論為「補件」並填寫理由後送出
- **THEN** 請求帶該最終結論與理由，送出成功

#### Scenario: 缺理由不可送出

- **WHEN** Reviewer 選擇需要理由的動作但理由欄空白
- **THEN** 送出按鈕停用，並提示理由為必填

#### Scenario: 非人工判斷不帶結論

- **WHEN** Reviewer 送出「確認通過」
- **THEN** 請求不含最終結論欄位

#### Scenario: 後端拒絕

- **WHEN** 後端以 400 拒絕處置
- **THEN** 工作台在處置區顯示後端錯誤訊息，案件資料維持不變，Reviewer 可修正後重送

### Requirement: 處置結果顯示固化徽章

處置成功後，工作台 SHALL 顯示結果狀態與後端回傳的一致性徽章，並重新取得案件列表、統計與該案詳情，
讓處理狀態即時更新。徽章 MUST 直接取自後端回應，工作台 MUST NOT 自行依建議與結論重算徽章。

#### Scenario: 顯示後端回傳的徽章

- **WHEN** 處置成功，後端回傳一致性徽章 `OVERRIDDEN`
- **THEN** 處置區顯示「已覆寫」徽章與結果狀態

#### Scenario: 處置後列表更新

- **WHEN** 處置成功、結果狀態為 `DISPOSED`
- **THEN** 列表中該案處理狀態更新為「已處置」，且抽屜不再顯示處置按鈕

### Requirement: 載入與錯誤狀態

工作台 SHALL 在資料載入時顯示載入狀態，在後端無法連線或回應格式不符契約時顯示錯誤訊息與重試入口。
回應未通過共用契約驗證時，工作台 MUST 視為錯誤，MUST NOT 以不完整資料渲染判定結果。

#### Scenario: 後端無法連線

- **WHEN** 案件列表請求失敗
- **THEN** 總覽顯示錯誤訊息與「重試」按鈕，不顯示空列表誤導為「沒有案件」

#### Scenario: 回應不符契約

- **WHEN** 詳情回應缺少必要欄位
- **THEN** 抽屜顯示資料格式錯誤訊息，不顯示檢查清單與處置按鈕

### Requirement: 案件搜尋

工作台 SHALL 在篩選控制項上方提供單一搜尋輸入框，以輸入字串模糊比對案件的**案件編號、申請人、
部門與說明**。比對 MUST 為子字串比對且不分大小寫，MUST NOT 要求完整相符。輸入的前後空白
MUST 被忽略；搜尋字串為空（或只有空白）時 MUST 視為未搜尋。輸入 SHALL 不需按下額外按鈕即生效。

搜尋 SHALL 作為**基底集合**的篩選：先套用搜尋，再套用分類與處理狀態兩個維度。
搜尋 MUST 反映在結果筆數上，但 MUST NOT 改變統計卡片的數字（卡片是固定總覽，
見「案件總覽統計與篩選」需求）。搜尋 MUST NOT 改變或清除當前的分類與處理狀態篩選。

搜尋沒有任何相符案件時，工作台 MUST 顯示空狀態並說明是搜尋造成的，
且 MUST 提供清除搜尋的方式。搜尋與排序 SHALL 在已結案案件頁面以相同行為運作。

#### Scenario: 以案件編號片段搜尋

- **WHEN** Reviewer 在搜尋框輸入 `2002`
- **THEN** 列表只顯示案件編號含 `2002` 的案件，不需輸入完整編號

#### Scenario: 以申請人搜尋

- **WHEN** Reviewer 輸入某申請人姓名的一部分
- **THEN** 列表只顯示該申請人的案件

#### Scenario: 不分大小寫

- **WHEN** Reviewer 輸入 `exp-2026`
- **THEN** 列表顯示案件編號為 `EXP-2026-…` 的案件

#### Scenario: 前後空白被忽略

- **WHEN** Reviewer 輸入的字串前後含空白
- **THEN** 搜尋結果與去除空白後相同；字串只有空白時視為未搜尋，列表不被縮減

#### Scenario: 搜尋與篩選同時套用且計數一致

- **WHEN** Reviewer 已選處理狀態「待審」並輸入一段搜尋字串
- **THEN** 列表只顯示同時符合搜尋與該狀態的案件，結果筆數等於列表筆數，統計卡片的數字不變

#### Scenario: 搜尋不清除既有篩選

- **WHEN** Reviewer 在已套用 EXCEPTION 分類篩選時輸入搜尋字串
- **THEN** EXCEPTION 卡片維持選取狀態，搜尋在該篩選之上生效

#### Scenario: 搜尋無結果

- **WHEN** 搜尋字串沒有任何相符案件
- **THEN** 列表顯示空狀態並說明沒有符合搜尋的案件，並提供清除搜尋的入口

### Requirement: 案件列表排序

工作台 SHALL 允許依**申請日期**與**案件編號**排序案件列表，排序入口為對應的欄位標題。
點選欄位標題 MUST 切換該欄的升冪／降冪，且 MUST 以可辨識的方向指示呈現當前排序欄與方向。
同一時間 MUST 只有一個排序鍵生效——點選另一欄 MUST 取代原本的排序，不得累加為多重排序。

預設排序 MUST 為申請日期由新到舊。套用或變更搜尋與篩選時，當前排序 MUST 被保留。
案件編號的排序 MUST 依編號的自然順序（數字段依數值比較），MUST NOT 讓 `EXP-2026-10` 排在
`EXP-2026-9` 之前。排序欄位缺值的案件 MUST 被排在該方向的末尾，MUST NOT 被從列表中移除。
排序 MUST NOT 改變任何計數。

#### Scenario: 預設排序

- **WHEN** Reviewer 開啟案件總覽
- **THEN** 列表依申請日期由新到舊排列，日期欄標題顯示降冪指示

#### Scenario: 切換排序方向

- **WHEN** Reviewer 點選已是降冪的申請日期欄標題
- **THEN** 列表改為由舊到新，方向指示改為升冪

#### Scenario: 改以案件編號排序

- **WHEN** Reviewer 點選案件編號欄標題
- **THEN** 列表依案件編號排序，且申請日期欄不再顯示排序指示

#### Scenario: 案件編號自然排序

- **WHEN** 列表同時含 `EXP-2026-9` 與 `EXP-2026-10`，以案件編號升冪排序
- **THEN** `EXP-2026-9` 排在 `EXP-2026-10` 之前

#### Scenario: 排序在篩選變更後保留

- **WHEN** Reviewer 已改為案件編號升冪，接著點選 EXCEPTION 卡片
- **THEN** 篩選後的列表仍依案件編號升冪排列

#### Scenario: 缺值排在末尾

- **WHEN** 某案件沒有申請日期，列表依申請日期排序
- **THEN** 該案件出現在列表末尾，且仍出現在列表中

#### Scenario: 排序不影響計數

- **WHEN** Reviewer 變更排序欄或方向
- **THEN** 所有卡片與處理狀態的計數都不變

### Requirement: 已結案案件頁面

工作台 SHALL 在案件總覽的主選單下提供獨立的「已結案案件」頁面，列出流程狀態為 `REVIEW_CLOSED`
的案件。此頁面的資料 MUST 由後端依流程狀態篩選取得，MUST NOT 由前端撈取全部案件後自行過濾。
案件總覽的預設列表與所有統計 MUST 維持排除 `REVIEW_CLOSED` 案件。

頁面的每一列 SHALL 含案件編號、申請人、金額、Agent 分類徽章（若有 run）與結案標示，
並 MUST 可開啟該案件的詳情抽屜。已結案案件的詳情 MUST NOT 顯示處置按鈕。
此頁面 MUST 有自己的網址，重新整理後 MUST 回到同一頁面。

此頁面 SHALL 提供與案件總覽相同行為的搜尋與排序（同一組比對欄位、同一組排序欄位與預設排序），
MUST NOT 各自實作一套不同的行為。此頁面 MUST NOT 顯示分類卡片與處理狀態篩選
（該頁的流程狀態固定為 `REVIEW_CLOSED`）。

#### Scenario: 已結案案件出現在專屬頁面

- **WHEN** Reviewer 開啟「已結案案件」頁面
- **THEN** 列表顯示流程狀態為 `REVIEW_CLOSED` 的案件，含帶有 Agent run 的已結案案件

#### Scenario: 已結案案件仍不進案件總覽

- **WHEN** Reviewer 回到案件總覽
- **THEN** 預設列表與統計都不含任何 `REVIEW_CLOSED` 案件

#### Scenario: 從已結案頁面開啟詳情

- **WHEN** Reviewer 點選已結案列表中的某案件
- **THEN** 詳情抽屜開啟並顯示該案完整歷程，且不顯示處置按鈕

#### Scenario: 頁面可由網址直達

- **WHEN** Reviewer 以已結案案件頁面的網址重新整理
- **THEN** 仍停留在已結案案件頁面，不跳回案件總覽

#### Scenario: 已結案頁面的搜尋與排序

- **WHEN** Reviewer 在已結案案件頁面輸入搜尋字串並點選案件編號欄標題
- **THEN** 搜尋與排序的行為與案件總覽一致，且頁面不顯示分類卡片與處理狀態篩選

### Requirement: 申請人與部門申請紀錄

工作台 SHALL 在 Reviewer 點選詳情抽屜中的申請人或部門時，以彈出視窗顯示該申請人或該部門的案件紀錄。
每一列 MUST 含案件編號、申請日期、金額、Agent 分類徽章與處理狀態，且 MUST 標示出當前開啟的案件。
點選其中另一筆案件 MUST 切換詳情抽屜到該案件。彈出視窗 MUST 可用關閉按鈕與 Esc 鍵關閉。

此彈出視窗 SHALL 只呈現既有案件資料的唯讀清單。工作台 MUST NOT 在此顯示風險分數、跨案件風險判定，
或任何「此人／此部門有問題」的結論性表述——跨案件風險判定不屬本階段範圍。
資料載入中 MUST 顯示載入狀態，請求失敗 MUST 顯示錯誤與重試入口，而非空清單。
該申請人或部門除當前案件外沒有其他紀錄時，MUST 明示「沒有其他申請紀錄」。

#### Scenario: 開啟申請人紀錄

- **WHEN** Reviewer 點選詳情抽屜中的申請人姓名
- **THEN** 彈出視窗顯示該申請人的案件清單，含案件編號、申請日期、金額、分類徽章與處理狀態

#### Scenario: 開啟部門紀錄

- **WHEN** Reviewer 點選詳情抽屜中的部門
- **THEN** 彈出視窗顯示該部門的案件清單

#### Scenario: 標示當前案件

- **WHEN** 清單中包含當前開啟的案件
- **THEN** 該列被標示為當前案件

#### Scenario: 切換到其他案件

- **WHEN** Reviewer 點選清單中的另一筆案件
- **THEN** 彈出視窗關閉，詳情抽屜切換為該案件

#### Scenario: 不呈現風險判定

- **WHEN** 某申請人的清單含多筆案件
- **THEN** 視窗只列出案件資料，不顯示風險分數、頻率警示或任何指控性結論

#### Scenario: 沒有其他紀錄

- **WHEN** 該申請人除當前案件外沒有其他案件
- **THEN** 視窗明示「沒有其他申請紀錄」，不顯示空白清單

#### Scenario: 請求失敗

- **WHEN** 申請紀錄請求失敗
- **THEN** 視窗顯示錯誤訊息與「重試」入口，不顯示為沒有紀錄
