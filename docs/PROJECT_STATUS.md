## 1. 為什麼重構

PM 已確認以 **CheckMate** 的 PRD 作為最新版本，Demo 也以此為主。舊版 expense-review-agent
（M1 Review Copilot）和 CheckMate 的產品模型有根本差異（流程動作、主管角色、判定詞彙、開發流程），
因此保留工程骨架（monorepo、NestJS、Prisma、CI、只能新增的稽核紀錄與 hash chain），
把領域模型整套換成 CheckMate 的。

**重構目標（2026-09-29 確認）**：先**追平 CheckMate Prototype**——預置的審查結果、人工處理例外、
審查歷史——並由後端與資料庫保存，取代原型的「只存在瀏覽器記憶體」。
尚未定案的規則條件不自行補完，只實作已定案的檢查。

### 現在能做什麼

- **工作台**：依處理進度分流（待處理／待補件／已完成初審／全部）；案件編號與申請人搜尋（AND）、
  初審建議複選（OR）；列表與右側詳情並排、可展開；上一筆／下一筆在目前篩選結果內循環。
- **案件詳情**：申請資訊、費用明細（未稅／稅額未提供時明示）、四個審查面向的檢查清單
  （未見異常／需確認／缺件／無法判斷／不適用分開呈現）、規則依據、依明細切換的模擬憑證、處理建議。
- **人工處理**：完成初審、人工確認通過（必填審核說明）、退回補件（必填補件內容，預先帶入缺少項目）；
  「建議通過」案件可批次完成（整批皆須合格，否則整批不執行）。原始建議不變，處理紀錄另存。
- **審查歷史**：EXP-2026-001 有兩次審查紀錄，可切換查看當時的建議、發現與憑證快照；
  歷史紀錄不能處理；顯示與前次相比的建議變化與已解決的問題（`review-case.md` 4.8）。
- **保存與追溯**：處理紀錄寫入資料庫，重新整理後仍在；每個案件有 hash-chained 稽核軌跡。

### 與 CheckMate Prototype 的差異

| 項目           | CheckMate Prototype          | 本 Repo                                                      |
| -------------- | ---------------------------- | ------------------------------------------------------------ |
| 資料保存       | 瀏覽器記憶體，重新整理即重設 | PostgreSQL；重設示範資料用 `pnpm --filter api db:reset`      |
| 規則把關       | 前端函式                     | shared 規則（前後端同一份）＋ DB 約束（最後一道防線）        |
| 重審差異摘要   | 只有歷史清單                 | 另外顯示與前次相比的變化（`review-case.md` 4.8 要求）        |
| 窄版費用類型欄 | 未套用設計規範的隱藏         | 並排時隱藏（依 Design System）                               |
| E-01 金額比對  | 純函式，無使用者入口         | 同樣無使用者入口；另用來驗證預置資料的「申請與憑證核對」結果 |

### 驗證紀錄（2026-09-29）

- CI 五關（lint、format:check、typecheck、test、build）全綠；shared 66 項、api 12 項單元測試，
  另有 demo 案例一致性檢查（故意改壞的資料會被擋下）。
- DB 治理約束逐項實測：非 TWD、Finding 無依據、處理歷史紀錄、例外案件無理由、偽造原始建議、
  重複處理、改寫或刪除審查紀錄、TRUNCATE 稽核事件，全部被資料庫拒絕。
- API 端到端 20 項（含 400／404／409 路徑、批次全有全無、hash chain 驗證）；
  同一案件 5 個同時送出 → 1 個成功、4 個 409，無 500。
- 以 headless Chrome 實際操作 27 項流程（處理、批次、退回補件、歷史、持久化、找不到案件），
  無 console 錯誤。

## 5. 對團隊的影響

- 遠端的 `Fanny`、`Nancy` 等分支是舊模型，無法直接合併；請以 `refactor` 為基準重新開分支。
- 第一次切到 `refactor` 要重建資料庫：`pnpm --filter api db:reset`（v4 是新的 migration 基準）。
- 本機需要 Docker（Postgres）才能跑 API；前端 dev server 會把 `/api` 轉到 `localhost:3000`。
- Demo 部署需要 Postgres 與 API 主機，比 CheckMate 原型（純靜態，部署在 Vercel）複雜，需提早確認環境。
